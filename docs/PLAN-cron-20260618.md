# FinSight 정기 수집 자동화 계획 (PLAN-cron-20260618)

> 본 문서는 [PRD-20260323](./PRD-20260323.md) 아키텍처의 **데이터 수집(GitHub Actions)** 구간을 구현하기 위한 계획이다.
> 백엔드 배치 [PLAN-backend-20260617](./PLAN-backend-20260617.md)에서 구현한 `src.collect`를 **GitHub Actions cron**으로 매일 자동 실행한다.

## 1. 목표
- 별도 서버 없이 **GitHub Actions(무료)** 스케줄러로 매일 자동 수집·적재한다.
- 정기 실행 옵션: **`uv run python -m src.collect`** (전체 종목, 최근 1개월, 기본 파라미터).
- 수동 실행(`workflow_dispatch`)으로 임의 기간/종목 재수집을 지원한다.
- 실행 로그를 아티팩트로 보관하고, 실패 시 알림으로 인지한다.

## 2. 동작 구조
```
GitHub Actions (cron, 매일) 
   └─ checkout → uv 설치 → uv sync → `uv run python -m src.collect`
        └─ Neon DB(DATABASE_URL, Secret) 에 일괄 수집·적재 (멱등 upsert)
        └─ logs/finsight_{to일자}.log → 아티팩트 업로드
```
- 수집 윈도우가 **최근 1개월(롤링)** 이므로, 하루 실패해도 다음 날 실행에서 누락분이 보완된다(멱등 upsert).
- DB 연결은 코드의 `get_database_url()`이 `postgresql://`를 자동으로 `postgresql+psycopg`로 정규화하므로 Neon 콘솔 문자열을 그대로 Secret에 넣으면 된다.

## 3. 스케줄 설계
- GitHub Actions의 `cron`은 **UTC 기준**이다. 한국시간(KST=UTC+9)으로 환산해 등록한다.
- 권장: **매일 08:00 KST 실행** → cron `0 23 * * *` (전일 23:00 UTC).
  - 국내장 마감(15:30 KST) 및 전일 미국장 마감 데이터가 반영된 시각.
- 주말 포함 매일 실행(암호화폐는 주말도 거래, 지수/주식은 휴장이라 건수 0 → 멱등이라 무해).
- 참고: 예약 실행은 러너 부하에 따라 **수 분~수십 분 지연**될 수 있고, 정확한 시각 보장은 안 된다.

| 목표 시각(KST) | cron (UTC) |
| --- | --- |
| 08:00 | `0 23 * * *` |
| 16:30 | `30 7 * * *` |
| 평일만 08:00 | `0 23 * * 0-4` (UTC 일~목 = KST 월~금) |

## 4. 사전 준비 (GitHub 저장소 설정)

### 4.1. Secret 등록 (필수)
`.env`는 커밋되지 않으므로 CI에서는 **저장소 Secret**으로 DB 연결 문자열을 주입한다.
1. GitHub 저장소 → **Settings** → **Secrets and variables** → **Actions** 탭
2. **New repository secret** 클릭
3. 입력 후 저장
   - **Name**: `DATABASE_URL`
   - **Secret**: `postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require` (Neon 콘솔의 connection string)

### 4.2. Actions 사용 설정
- Private 저장소에서 Actions가 비활성화되어 있으면: **Settings → Actions → General → Allow all actions and reusable workflows** 활성화.
- (선택) 실패 알림: GitHub은 기본적으로 워크플로 실패 시 등록 이메일로 통지한다. **Settings → Notifications**에서 확인.

## 5. 워크플로 파일

경로: **`.github/workflows/collect.yml`**

```yaml
name: collect-daily

on:
  schedule:
    # UTC 기준. 매일 23:00 UTC = 08:00 KST(다음 날)
    - cron: "0 23 * * *"
  workflow_dispatch:
    inputs:
      to_date:
        description: "수집 종료일 yyyymmdd (생략 시 당일)"
        required: false
        default: ""
      from_date:
        description: "수집 시작일 yyyymmdd (생략 시 to일자 -1개월)"
        required: false
        default: ""
      symbol_id:
        description: "특정 symbol_id (생략 시 전체)"
        required: false
        default: ""

# 동일 워크플로 중복 실행 방지 (이전 실행 완료까지 대기)
concurrency:
  group: collect-daily
  cancel-in-progress: false

permissions:
  contents: read

jobs:
  collect:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Install uv
        uses: astral-sh/setup-uv@v6
        with:
          enable-cache: true

      - name: Set up Python (.python-version)
        run: uv python install

      - name: Install dependencies (lock 고정)
        run: uv sync --frozen

      - name: Run collection
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
        run: |
          ARGS=""
          if [ -n "${{ github.event.inputs.to_date }}" ];   then ARGS="$ARGS --to-date ${{ github.event.inputs.to_date }}"; fi
          if [ -n "${{ github.event.inputs.from_date }}" ]; then ARGS="$ARGS --from-date ${{ github.event.inputs.from_date }}"; fi
          if [ -n "${{ github.event.inputs.symbol_id }}" ]; then ARGS="$ARGS --symbol-id ${{ github.event.inputs.symbol_id }}"; fi
          echo "실행: uv run python -m src.collect $ARGS"
          uv run python -m src.collect $ARGS

      - name: Upload log artifact
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: collect-log-${{ github.run_id }}
          path: logs/*.log
          retention-days: 14
          if-no-files-found: warn
```

### 5.1. 동작 설명
- **schedule 실행 시**: `inputs`가 모두 비어 있어 인자 없이 `uv run python -m src.collect` → **전체 종목, 최근 1개월**(목표 옵션).
- **workflow_dispatch 실행 시**: 입력값이 있으면 `--to-date/--from-date/--symbol-id`로 전달(초기 백필·특정 종목 재수집 용도).
- `uv sync --frozen`: 커밋된 `uv.lock`으로 재현 가능한 설치(잠금과 불일치 시 실패).
- `uv python install`: `.python-version`(3.12)에 맞는 인터프리터 자동 설치.
- `DATABASE_URL`은 Secret으로만 주입(로그/코드에 노출 금지).
- 로그는 러너에서 휘발되므로 `logs/*.log`를 **아티팩트로 14일 보관**(`if: always()`로 실패 시에도 업로드).

## 8. 운영 고려사항 / 리스크
| 항목 | 내용 | 대응 |
| --- | --- | --- |
| cron 시간대 | GitHub cron은 UTC | KST→UTC 환산하여 등록(3장) |
| 예약 지연 | 러너 부하로 실행이 지연/누락될 수 있음 | 최근 1개월 윈도우 + 멱등 upsert로 누락 자가복구 |
| 스케줄 자동 비활성화 | 공개 저장소에서 60일간 커밋 없으면 schedule 비활성화 | 주기적 커밋 또는 수동 재활성화 |
| 무료 사용량 | Private 저장소는 Actions 분(月 2,000분) 제한 | 실행 ~2분 내외로 충분, Public은 무제한 |
| 비밀정보 | 연결 문자열 노출 위험 | Secret 사용, 로그 출력 금지, 1000byte 로그 절단 적용됨 |
| 외부 API 실패 | 원천(FDR/Yahoo) 일시 오류 | 종목 단위 실패 격리(배치 지속) + 익일 재수집 |
| 동시 실행 | 수동+예약 중복 가능 | `concurrency` 그룹으로 직렬화 |
